## О проекте

**sql-explorer** — консольное Java-приложение для управления учебными данными (студенты, курсы, оценки), реализованное на чистом JDBC без ORM-фреймворков. Проект демонстрирует ручную работу с реляционной базой данных, включая явное управление транзакциями, собственную иерархию исключений и полную контейнеризацию через Docker Compose.

### Ключевые возможности

- **Полный CRUD** — для студентов и курсов
- **Ручное управление транзакциями** — перевод студента на другой курс как атомарная операция (commit/rollback)
- **Собственные исключения** — `DAOException` и `EntityNotFoundException` вместо утечки `SQLException` наружу
- **Защита от SQL-инъекций** — все запросы через `PreparedStatement`
- **Связь Many-to-Many** между студентами и курсами через промежуточную таблицу `grades`
- **DAO-слой** — изоляция логики доступа к данным от бизнес-логики и консольного интерфейса
- **Полная контейнеризация** — приложение и база данных поднимаются одной командой `docker compose up`

## Архитектура

### Ключевые архитектурные решения

**`ConnectionManager`**
Единая точка создания соединений с базой (Utility Class с приватным конструктором). Параметры подключения читаются из переменных окружения (`DB_URL`, `DB_USER`, `DB_PASSWORD`) с дефолтными значениями для локального запуска — это позволяет одному и тому же коду работать как при запуске напрямую с хоста, так и внутри Docker-сети без изменений.

**DAO-слой (`StudentDao`, `CourseDao`, `GradeDao`)**
Каждый класс отвечает за доступ к данным ровно одной сущности. Методы возвращают `Optional<T>` там, где результат может отсутствовать (`findById`), чтобы явно обозначить необходимость обработки пустого случая.

**Обработка ошибок (`exception`)**
Вместо распространения `SQLException` (checked exception) по всем сигнатурам методов используется собственная иерархия непроверяемых исключений:
- `DAOException` — базовое исключение слоя доступа к данным, оборачивает исходный `SQLException`
- `EntityNotFoundException` — бросается, когда операция `update`/`delete` не находит запись по `id` (`executeUpdate()` вернул 0 затронутых строк)

Консольное меню (`Main`) ловит эти исключения и показывает пользователю понятное сообщение вместо падения программы со стектрейсом.

**Транзакции (`GradeDao.transferStudentToCourse`)**
Перевод студента на другой курс требует удаления старой записи и вставки новой как единой атомарной операции:
- `connection.setAutoCommit(false)` — отключение автокоммита перед началом транзакции
- Обе операции (`DELETE` + `INSERT`) выполняются в рамках одного соединения
- `connection.commit()` — фиксация изменений при успехе обеих операций
- `connection.rollback()` — полный откат при возникновении ошибки на любом из шагов, включая нарушение бизнес-правил (например, попытку перевести на тот же курс)
- `finally`-блок гарантирует закрытие соединения независимо от исхода

**Защита от SQL-инъекций**
Все запросы построены через `PreparedStatement` с параметризацией (`?`) — ни один пользовательский ввод не попадает в SQL-текст напрямую.

**Контейнеризация (`Dockerfile`, `docker-compose.yml`)**
- `Dockerfile` использует multi-stage build: первый этап (`maven:3.9-eclipse-temurin-17`) собирает jar, второй (`eclipse-temurin:17-jre-alpine`) содержит только JRE и готовый артефакт — это уменьшает финальный размер образа, так как Maven, исходники и промежуточные файлы сборки не попадают в конечный образ
- `docker-compose.yml` поднимает два сервиса: `postgres` (база данных) и `app` (само приложение)
- `healthcheck` у `postgres` и `depends_on: condition: service_healthy` у `app` гарантируют, что приложение не попытается подключиться к базе раньше, чем она реально готова принимать соединения
- Внутри Docker-сети сервисы обращаются друг к другу по имени сервиса (`postgres`), а не по `localhost` — поэтому `DB_URL` внутри контейнера отличается от строки подключения при локальном запуске

## Запуск

### Требования

- Docker и Docker Compose

### Запуск через Docker

Приложение и база данных поднимаются одной командой из корня проекта:

```bash
git clone https://github.com/kirinnah/sql-explorer.git
cd sql-explorer
docker compose up --build
```

Флаг `--build` обязателен при первом запуске и после изменений в коде — иначе Docker может использовать закэшированный образ приложения.

Так как приложение консольное и ожидает ввод через `Scanner`, для корректной интерактивной работы удобнее запускать так:

```bash
docker compose run --rm app
```
